# RULE MICRO-TECHNIQUES — good vs bad, banked

## GOOD RULE vs BAD
| Good | Bad |
|---|---|
| Absurd premise followed with total sincerity | Winking at the absurdity (performer signals joke) |
| Internal logic held without exception (rules apply always) | Convenient exceptions (logic bends for easy laughs) |
| Consequences explored honestly (what follows IS what follows) | Randomness dressed as logic (non sequiturs in rule clothing) |
| Straight face maintained to the end | Breaking first (comic laughs = permission to dismiss) |
| Game discovered, then heightened (UCB shape) | Game asserted, never played (premise announced, abandoned) |

## Bank
1. **Sincerity inside absurd (Seinfeld pad straight-faced).** The stupider the premise, the straighter the face. Sincerity IS the engine; winking stalls it.
2. **No-exception audit.** List the premise's rules. Check every beat: any violation? One convenience-break and the room stops tracking logic (why follow rules the comic won't?).
3. **Consequence engine.** For each beat ask "if this is true, what else is true?" (Andrew formula step 6). Answers are the next beats. Logic generates material.
4. **Straight-face discipline.** Rehearse absurd bits flat. Any laugh-at-own-joke in rehearsal = cut or reframe. The room laughs; you don't.
5. **Game-first discovery.** Improvise inside the premise 3+ times before writing. The game that emerges in play beats the game you planned.
6. **Heighten inside rules (UCB).** Bigger SAME-direction moves, never sideways. Rules constrain escalation productively (creativity loves a cage).
7. **Literalism as weapon.** Take the premise more literally than anyone would. Hyper-literal readings of absurd rules generate automatic bits.
8. **Deadpan register check.** If the bit needs energy to work, the rules are weak. Strong rules work whispered. Test at 50% energy.
9. **Rule-break = finale only.** The single allowed exception goes last (rule proves itself by surviving everything, then the exception detonates it).
10. **Bogus-logic ledger.** Write the premise's "physics" down (3-5 laws). New bits must derive from the ledger or start a new bit. No freeloading.
